# 原生 Task Conductor

主会话需要周期、重复流程、DAG 或离开当前宿主会话后继续执行时使用本文。普通独立协助使用 pbot_agent。

## 准备能力

先通过当前宿主的原生工具发现查找 Task Conductor，并加载 using-task-conductor 技能，以实际 MCP schema 为准。工具未直接显示不等于未安装；技能可用时，按技能处理连接或排障。

以下安装命令只适用于 Pi。技能缺失时，用 `pi list` 检查插件及资源启用状态；按当前包要求核对宿主兼容性。需要替换旧接入包时先读上游升级说明，保留任务历史。确未安装且已有安装授权时使用工作区安装命令：

```bash
pi install --local npm:task-conductor-plugin
```

安装后请用户在当前 Pi 会话执行 `/reload`，再执行 `/skill:using-task-conductor` 处理服务安装、setup 与 MCP 接入；这些会话命令不能通过 Bash 代执行。已发现技能时可直接读取并继续可执行的步骤。复用已有连接，按 provider-connections 核对当前会话的连接与认证。

在 dsh 中，按上游适用于当前版本的方式加载技能，并通过 dsh 原生 MCP 连接已有服务；不把 Pi 插件声明、`pi install` 或 `/reload` 用作 dsh 接入。服务端节点的执行器、认证与环境仍按其自身配置核对，不假定与当前 dsh 会话相同。

能力不可用时说明依赖它的工作受阻，继续其他已授权工作；不以循环等待或后台子会话替代持久调度。

## 委派与许可

提交前明确输入、工作目录、所需工具与模型认证、输出和完成条件。周期任务还须明确频率、时区、授权范围及每轮数据来源、期间与时点。

核实节点所需的工具、技能、Python 环境和批准通道。节点任务限定为本次交付，不再递归委派。

没有可靠批准通道时，不安排需人工批准的后台操作或无人值守交易；不得绕过批准要求。调度和恢复任务不扩大已有授权。独立复核使用新的独立节点，只查询和计算；协调器验收不等于专业复核或业务批准。

## 核对与保存

任务定义、执行和节点分别用 taskId、runId 和节点 ID 标识。提交响应不明时先查已有标识；未取得 ID 时，按接口可用的请求关联、任务列表、提交时间或任务特征查找并核对。未能确认是否已创建时保留未知状态，不重复提交。实时状态查询 Task Conductor；项目资料只保存必要定义、标识和有时点的结果依据。

取消当前执行与停止未来周期分别操作，并查询确认。pbot_agent stop 或当前宿主关闭不停止 Task Conductor。报告已设置调度须有实际提交结果；报告本轮成功须核对本轮产物与完成条件。
