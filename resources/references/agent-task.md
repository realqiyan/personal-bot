# 原生 Agent Task

主会话需要周期、重复流程、DAG 或离开当前 Pi 后继续执行时使用本文。普通独立协助使用 pbot_agent。

## 准备能力

先通过 Pi 原生工具发现查找 Agent Task，并加载 using-agent-task 技能，以实际 MCP schema 为准。工具未直接显示不等于未安装；技能可用时，按技能处理连接或排障。

技能缺失时，用 `pi list` 检查插件及资源启用状态。确未安装则说明需要 Pi 1.4.0+，经用户同意后使用工作区安装命令：

```bash
pi install --local npm:@realqiyan/agent-task-plugin
```

重载后通过 `/skill:using-agent-task` 处理服务安装、setup 与原生 MCP 接入。复用已有原生连接，不在聊天中索取凭据值。插件可见不证明服务已连接，执行器 ready 不证明模型认证和执行成功。

能力不可用时说明依赖它的工作受阻，继续其他已授权工作；不以循环等待或后台子会话替代持久调度。

## 委派与许可

提交前明确输入、工作目录、所需工具与模型认证、输出和完成条件。周期任务还须明确频率、时区、授权范围及每轮数据来源、期间与时点。

核实节点实际具备的工具、技能和 Python 环境，不假定它继承主会话能力或批准通道。节点任务限定为本次交付，不再递归委派；普通 Pi 节点不是受限专家，这些约定也不是宿主隔离。

没有可靠批准通道时，不安排需人工批准的后台操作，不降低权限或开展无人值守交易。独立复核使用新的独立节点，只查询和计算；协调器验收不等于专业复核或业务批准。

## 核对与保存

任务定义、执行和节点分别用 taskId、runId 和节点 ID 标识。提交响应不明时先查原标识，不换标识重复创建。实时状态查询 Agent Task；项目资料只保存必要定义、标识和有时点的结果依据。

取消当前执行与停止未来周期分别操作，并查询确认。pbot_agent stop 或 Pi 关闭不停止 Agent Task。报告已设置调度须有实际提交结果；报告本轮成功须核对本轮产物与完成条件。
