# 项目整理与维护

让工作区资料准确反映实际进展，使下一次接手能了解目标、当前结果、依据和真正未完成的事项。根据已有证据更新资料，由模型判断检查深度和更新是否完整，不要求固定报告或逐轮总结。

## 范围与依据

整理时默认检查当前任务、直接关联资料及进行中的任务；用户指定范围时遵从其要求。重点检查当前任务和直接关联正文，其他进行中任务先读入口、状态和未决事项，发现关联变化或矛盾后再深入。仅复用任务定义时，检查该定义和本次所需的关联资料，不扩大为整体整理。用户要求整体整理时扩大检查。

从根 AGENTS.md 和相关目录入口定位资料，结合当前对话、已有成果及必要的目录检查，发现未进入索引的任务或结果。索引不是任务的完整事实源；文件存在、修改时间或一次成功调用本身都不证明任务完成。无法核实的状态保留不确定性，不根据缺失资料猜测结论。

检查实际进展、正文和入口是否一致。例如项目已经记录连接恢复，相关手册仍写断开，应依据实际验证的时间和范围修正，不能推广为当前所有接口均可用。

## 更新所属资料

先搜索同主题正文，直接更新所属资料，其他位置引用，不另建维护日志或重复总结。按影响同步项目 README.md、相关长期事务、知识、能力提供方手册及资料导航；没有新证据或状态变化就不改。

- 记录结论、日期、适用范围、依据和实际存在的未决问题，区分事实、推断、建议和用户已确认决策。来源注明链接、文件、版本或日期，用户决策注明确认范围。
- 结论变化注明原因，新决策关联被替代记录，保留必要历史。新的局部验证不能覆盖其他未验证条件。
- 长期保存结论及最小充分数据：无法可靠恢复的输入快照、来源与数据口径、复现参数和代码、用户要求的最终明细。不新增长期保存的操作流水账、重复产物或可可靠重算的中间数据。
- 金融结果保留数据时点、单位和计算来源；回测与计算引用实际产物路径、可复现命令与必要输入。
- 长期建议引用项目证据，已有可复用结论归入 knowledge/。长期知识按主题命名，需要保留历史的研究和决策按日期与主题命名。维护资料不要求创建新技能。

根 AGENTS.md 用一棵 text 目录树维护资料索引，已确认的工作区约定单独保留。入口变化时更新现有树，展开到有资料的主题或项目目录；节点注释只说明用途。未完成项目加 [TODO]，完成后移除；结论和未决事项留在项目正文，导航用链接引用。

## 记忆复用与修正

从入口定位同主题正文。入口未命中时，再用主题、别名或项目名查找相关资料，不把索引缺项当成资料不存在。常用信息通过入口更容易找到，详细内容仍留在所属正文；低频或已完成只影响导航，不构成删除证据的理由。

复用结论时核对来源、时点、适用范围和关键前提。历史验证不证明当前可用；接口版本、数据口径或关键输入变化时，标出受影响结论与需重核部分。只有新的验证证据才能更新验证状态，整理资料本身不代表补做了验证。

新证据与旧结论冲突时，先区分对象、时期和条件。能确认被取代的内容更新原文并保留必要历史与原因；尚不能解释的冲突明确保留，不因日期较新就覆盖。用户明确纠正的偏好或约束按其确认范围修正；从行为推测的偏好保持为推断，不因重复出现就写成已确认约定。

已解决问题先作为带来源、条件和验证结果的案例保存在所属项目。确有跨任务用途时提炼到 knowledge/ 并引用原证据；失败案例同样保留失败条件。有复用需求且方法足以指导执行时，再提出技能化建议，不因一次成功或固定次数自动创建技能。

## 任务定义与复用

复杂任务需要长期保存时，在所属项目正文记录交付用途、必要证据、可接受限制和完成条件，沿用请求与已有约定，不为普通问答另建规格文件。目标变化时说明哪些交付条件随之变化，不在结项时暗自降低要求。

重复分析或报告保存可复用定义，按实际需要包含：指标公式与分母、数据来源、对象与筛选范围、期间与时区、分组与比较基准、输入和执行入口、产物位置及核验条件。定义留在所属项目或长期事务，单次数据与结果作为有时点的证据引用，不写入包内技能或参考文件。

用户要求按上次口径重做时，先读已有定义与必要证据，沿用已确认选择。仅当歧义影响本次结果时提问；“本周”“最近”等期间按本次请求确定，不沿用旧报告日期。检查来源与定义是否适用于本次请求：需要当前数据时，不以历史快照替代；复现历史结果时，沿用指定输入。口径变化需说明对可比性的影响。涉及分析核验时使用 [analysis-validation 技能](../analysis-validation/SKILL.md)。

保存周期、步骤或待办不代表已建立调度，也不授予未来操作许可。外部任务资料只保存必要定义、服务返回的任务、运行与节点标识，以及有时点的结果依据；实时状态以任务服务查询为准。复用或结项涉及外部任务时，由主会话按对应技能核对实际状态与后续执行安排，仅修改文档不会停止任务。

## 成果归集与清理

用户要求整理或结项时，检查范围内项目目录及 scratch/ 等位置的临时报告、脚本和数据。将有用信息并入项目正文，将必要证据、引用数据及复现代码和参数保存到对应 projects/<名称>/，不把临时报告逐份搬入或重复保存。

保留支撑结论的最小充分资料。数据会过期或来源仍可访问，不代表能重新取得同一份数据；结论依赖的不可恢复快照应保留。可可靠重新获取或重算、且不承担证据作用的数据不必长期保存。

确认有用信息已保存、引用和复现路径已更新后，清理已被吸收的临时报告、无用试验脚本、重复下载及不再需要的中间产物。不能只凭文件年龄、所在目录或未找到引用决定删除，也不整目录清空 scratch/。仍在使用、跨项目共享或归属与价值不明的文件暂留，说明影响清理的具体疑点。

清理仅限本次整理范围内的临时产物，不删除正式资料、历史交易记录或备份，不擅自改写历史记录。仅因新结果触发资料同步时，不自行扩大为文件清理。

## 项目结项

依据已确认的目标和交付条件判断完成状态，核对必要成果、证据与复现入口确实可用，再同步项目入口与相关导航。操作或专家返回成功不等于交付条件满足。交付可以带有适用限制；满足本次用途后，可选深化研究不自动成为待办。已有必需工作未完成、关键证据冲突或目标不清时，不自行标记完成；记录具体缺口，只在影响判断时向用户澄清。

结项保留结论、必要证据、复现入口和已知限制，不要求另建结项报告或移动项目目录。

## 完成与边界

修改后核对正文、引用和状态是否一致，判断下一次接手是否会得到错误认识。公式或代码变更时验证受影响行为；通过后只因新修改、失败或未决疑点扩大检查。区分本地固定数据测试与外部服务验证，前者不证明后者。

项目声明依赖，使用可移植路径；路径或命令变化时同步引用。Git 只纳入长期需要的源码、说明与已授权输入，排除临时产物、运行环境、机器配置、凭据、账户标识和券商配置。在 Git 仓库中修改资料后运行 `git diff --check`。

答复简述实际更新、验证、清理范围及重要未决问题，不套固定模板，也不宣称已经检查未读取的资料。

在已有授权内直接修正资料和保存成果。新增长期行为要求或改变角色职责需用户确认，已明确授权的修改不重复询问。发现进行中任务或资料缺口，不自动开展那些任务、补做外部验证或执行交易。需要能力调用或接入变更时使用对应技能入口，不能用文档修改代替工具权限或内部状态变更。
