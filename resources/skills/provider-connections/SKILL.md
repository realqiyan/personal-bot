# 原生工具接入

从工作区 `providers/AGENTS.md`、对应 `<id>/GUIDE.md` 和用户给出的资料定位工具。已有工具优先复用，不把日常调用变成重新接入。

## CLI

通过 Bash 使用原生命令。先读版本和本次所需子命令的 help，参数、默认值和校验以当前安装版本为准。按任务需要查看可信文档或源码，不预先遍历和转写完整接口。

复用原生登录与 profile。需要安装、修改认证或切换账户时先明确用户意图；不索取、输出或保存凭据值。命令使用实际工作目录，路径、标准输入和输出遵循原生约定。

## MCP

使用 Pi 原生 MCP 配置与工具，不建立私有连接或另一份目录。先检查已有接入与配置来源；用 `/mcp` 查看连接、认证、工具或重连。需要从 Bash 配置时，先读 `pi mcp --help` 及相关子命令帮助。

新增 MCP 默认只接入当前项目。从工作区根目录执行 `pi mcp add --local <server> ...`，写入该项目的 `.pi/mcp.json`；删除项目连接也使用 `pi mcp remove --local <server>`。Pi 的 add/remove 不带 `--local` 会修改用户级配置，不能依赖原生命令默认值。第三方 setup 或接入向导也须先核对配置范围；不能指定项目范围时，使用原生项目配置，不直接接受全局默认值。只有用户明确要求跨项目使用时才修改用户级配置。

用户级配置位于当前 Pi agent dir 的 `mcp.json`，项目级配置由 Pi 的项目信任规则加载。项目同名配置可能覆盖用户级配置，修改前核对并保留无关条目。已有用户级连接不自动迁移或删除；需要迁移时先确认范围。凭据复用原生认证或环境变量引用，不把凭据值写入项目文件。接入后核对配置来源确为当前项目，不能仅凭工具可见判定范围正确。

通过原生工具搜索或 codemode 按需取得当前 schema 和调用结果。外部修改配置后使用原生 `/reload`；配置已保存不代表连接成功，连接成功不代表业务已验证。

## 验证与手册

接入验证只执行本次获准的查询，不执行交易或账本变更。连接受阻时报告具体缺口，继续不依赖连接的准备；不自动安装或反复重配。

每个工具在 `providers/<id>/GUIDE.md` 保留：
- 用途、原生入口、可信资料位置及适用版本。
- 工作区特有的数据口径、单位、时区、分页、标识关系和限制。
- 少量无凭据示例与容易误用的前提。
- 必要的真实验证结论和证据引用，区分已验证与待确认。

`providers/AGENTS.md` 只做导航和已确认的选用约定。不复制完整 help、schema、工具目录或权限表，不把排查流水放进长期手册。历史证据留在原项目，用引用连接。

调用结果按原生协议解释。进程退出成功或协议成功不代表业务完成；超时、断连和取消不证明未执行。结果不明时先查询原生状态，不为补结果、恢复会话或修复文件而重发可能已产生副作用的操作。
