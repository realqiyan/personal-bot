# 模型上下文

本文说明 Personal Bot 提供哪些指令、由谁加载，以及本地检查能证明什么。宿主自己的系统提示、用户配置和模型传输格式由 Pi 或 dsh 管理。

## 内容取舍

常驻内容用于首次任务就需要作出的判断：职责、资料位置、任务授权、结果核验和异常后的操作。只解释内部执行机制的内容放在开发文档。具体工具的参数、分页、通知领取和状态语义留在工具契约中。

| 内容 | 放置位置与理由 |
| --- | --- |
| 工作区目录用途 | 公共提示中保留完整用途表，根 AGENTS 模板保留导航；新建资料不依赖模型先选择维护技能。已有用户布局和约定优先 |
| 授权、核验与未知副作用 | 公共提示统一说明；异常通知只补本次故障需要的恢复方法 |
| 协调与专家交付 | 各自角色中说明，工作区同名职责补充继续加载 |
| 团队公开范围与续读 | 专家处理团队任务时加载 team-member；普通专家不常驻收到团队工作说明 |
| 项目维护与工具接入 | 技能目录提供名称、用途和读取入口；正文在相应任务中读取 |
| Python 与指标/回测 | 计算先读 compute；仅涉及指标或回测时再读 compute-finance，保留口径、暖机、缺失值和市场约束 |
| Task Conductor | 协调者需要周期、DAG 或持久执行时读取参考及上游技能；接入按当前版本要求，不在模型资料中固定开发基线 |
| 历史摘要 | 独立短提示，只处理本次历史文本；保留决定、建议、尝试、完成及不确定性的区别 |

角色和工具说明不再重复解释父聊天历史、进程、代次、结果持久化、宿主间参数转换等机制。需要模型实际执行的要求直接表达，例如委派提供目标、必要依据、约束和交付要求。异步任务要读哪个结果、分页如何继续、暂停后是否仍有在途工作会改变下一步操作，不能当作文案冗余删去。

2026-11-07 审查保留目录表后的包内常驻正文：公共约定加协调者由 2872 减至 1784 字符（约 38%），公共约定加普通专家由 2403 减至 1576 字符（约 34%）。这里只计文件的 UTF-16 长度，不包括宿主提示、工具 schema、用户资料与动态任务，不是 token 数或实际模型费用；首轮没有团队任务时不计 team-member。

## Pi

主会话第一次任务保留 Pi 原生系统提示、工具、AGENTS 等上下文文件、技能元数据和 cwd，再增加公共约定、协调者及工作区职责补充、精简环境。专家使用通用专家角色和同名工作区补充；原生文件由专家 cwd 决定，pbot 职责补充从原工作区读取。

包内主会话技能由 package.json 的 `pi.skills` 声明，遵守原生 no-skills 和包级过滤。专家使用其显式 noSkills 选项，原生工具按宿主规则决定技能是否可见。普通任务不包含技能或提示模板正文；读取技能或展开原生模板时才加入。

before_agent_start 完整读取公共约定及角色后更新 section。读取失败显式取消本轮，避免宿主捕获 hook 错误后继续执行。角色补充在下次工作周期读取；原生 AGENTS 和技能目录经 reload 更新。`/pbot init` 提示新建 AGENTS 的加载时机，不自动重载活动协作，也不另行复制一份根文件进提示。

未变的 section 不重复追加，变更只产生原生差量。有效系统内容仍会随宿主后续请求传递，不能把差量去重当成模型不再收到这些内容。工具声明独立于系统提示，也计入模型上下文；原来四个工具分别附加的两条公共指南已删除，原生 codemode 已说明 await、超时和结构化结果检查。

团队任务才增加团队目标、职责与操作说明；公共消息按 teamId/seq 和当前分支去重，后续安全边界补充未见消息。原生压缩可能移除已见原文，所需证据通过团队 read 重新读取，不为恢复原文自动重注整段历史。

## dsh

主会话使用自己的原生 preset，专家在 create/resume 时通过原生 composeFrom 应用父会话的 preset。标准 preset 提供的文件工具、AGENTS、技能发现等因而在专家首轮也可见。专家工具限制在组合后生效，保留团队通信，排除协调管理和原生 subagent_fork 等委派工具；不把工具选择称为执行隔离。

公共约定和角色在 system-prompt/assemble 当次读取，工作区角色修改在下一次实际请求中可见，不再滞后一轮。原生 complete persona 按宿主规则覆盖普通提示 section；pbot 不强制绕过。因此不能保证显式使用完整自定义 persona 的会话同时收到 pbot 公共约定和角色，选择这种 persona 时由用户维护其完整行为要求。

包内技能在 Host 层用原生 SkillFilesystem 注册一次，只提供包目录。项目和用户技能交给 preset 的原生 provider，保留 `.dsh/skills`、`.agents/skills`、用户目录与包技能的原生优先级及文件更新监听。noSkills 关闭专家的模型技能目录与 skill 工具；用户显式输入 `/技能名` 仍按宿主原生手势处理。

首次普通请求包含宿主系统提示、pbot 公共约定和角色、工具声明，以及原生 AGENTS、环境和技能目录消息。未变的原生内容不会在下一次输入时重复追加。工具 schema 在普通 executor 中独立提供；PTC 使用原生 run_code 和工具目录，不由 pbot 再造包装。

团队简报从动态 system section 移到 pre-step 已接纳的团队上下文，与公共原文使用既有 pbot-team-context 来源。事件队列先处理 turn/start，再准备首个请求；即使没有公共消息，首轮也得到共同目标、成员职责和团队操作说明。简报每次团队发言一次，公共序号在实际消费后才确认。被原生准入拒绝的内容不标记为已读，后续明确批次仍能获取；人工输入不追加新团队内容。

## 环境与历史

模型环境保留 `workspaceRoot`、`resourceRoot`、`python.state` 和就绪时的 `python.directory`。实际 cwd 使用宿主上下文，Python 准备日志保留在 `/pbot status`；计算参考提供诊断和重试入口。目录位置、Python 是否就绪和完整错误分别服务于资料定位、执行选择和排障。

两种历史摘要调用都直接使用专用提示和当前问答/下层摘要，带时段和未完成标记。不加载公共约定、角色、用户职责补充、AGENTS、技能、团队或环境，不提供工具。长文本按预算分段再汇总；查询、空会话和资源加载不会自动发起摘要。完整历史原文保留。

## 验证边界

真实 SDK 检查观察首次任务准备出的系统内容、工具声明、原生消息来源与后续差量；以临时文件的路径、原文和结构化状态作断言，不对产品提示词全文或句子做快照测试。Pi 使用真实 `_prepareRun` 观察认证前的准备结果，失败取消另通过真实 custom-message run 核对原生 abort 信号。

本地上下文组装可证明资料出现的位置、时间和去重，不能证明模型理解、工具选择或专业判断。成功模型、外部服务、完整 Web/桌面及平台验收按[验证记录](validation.md)注明实际范围。用户资料、职责补充、历史与备份不因本次审查被改写。
