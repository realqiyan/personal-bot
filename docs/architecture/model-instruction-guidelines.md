# 模型指令编写原则

修改 Agent 实际可见的内容及其加载方式时遵循本文。范围包括各宿主主会话与 ACP worker 的公共提示、角色、动态环境、工具说明、技能、参考资料、模板及历史摘要提示。本文方法论**仅面向运行时模型上下文**，与面向开发者的仓库技术文档（`AGENTS.md`、`docs/`）严格分开，不将仓库架构或构建实现写进 `resources/`。当前加载方式见[模型上下文](model-context.md)。

## 从实际上下文出发

以宿主实际组装的内容判断取舍，尤其检查新会话第一次任务。同时考虑宿主提示、用户资料、工具声明和技能目录，避免只看某个 Markdown 文件。

每段指令应有具体用途：帮助模型作什么决定、执行什么操作，或避免什么已知错误。根据用途保留、合并、删除、条件加载或按需读取，不以字数最少为目标，不加入没有明确需求的泛化约束。

## 直接说明要做什么

使用自然、直接的语言，写清职责、操作入口、参数含义和下一步。内部架构与执行机制只在改变实际操作时说明，其余留在开发文档。

## 不增加泛化流程

按用户请求和已有约定推进，不自行补入通用的证据收集、授权核对、审批、独立复核或业务验收流程。权限和确认机制沿用宿主、凭据、外部服务及用户约定；不通过提示掩盖或绕过实际执行限制，保留直接影响操作的事项（如配置作用域、凭据引用，以及结果未知时先查状态、避免重复执行）。

## 保留实用细节，按用途放置

| 内容 | 放置要求 |
| --- | --- |
| 首次任务就需要的职责与资料位置 | 放在公共提示或对应角色中 |
| 工作区目录用途与组织规范 | 保留首轮可见的目录说明和模板导航；已有用户布局与约定优先 |
| 工具参数、分页、状态和结果入口 | 放在工具契约中，避免其他提示重复完整说明 |
| 维护、接入、计算及调度方法 | 通过技能或参考资料按需读取，正文包含能实际执行的方法与关键口径 |
| 动态环境与错误 | 提供当前操作需要的字段；详细诊断留在状态或日志入口 |
| 历史摘要 | 使用专用提示与待总结资料，不混入普通工作角色和无关技能 |

优先使用宿主已有的资源发现、技能、工具、配置和上下文去重机制。加载缺失、时序错误或重复注入问题应修代码，不用提示词弥补。

## 验证要求

加载行为用真实宿主 SDK、本地文件和进程检查来源、首轮出现时机、后续更新、条件加载及去重；不编写断言提示词文案或全文快照的测试。
